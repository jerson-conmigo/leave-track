### B30 — PGlite lifecycle and CI memory (2026-11-26)

**Evidence.** The CI log ended with "The operation was canceled." after `tests/db/schema.test.ts`.
That text is GitHub's job-cancellation message (manual, concurrency or timeout); a Vitest failure
prints FAIL lines and exits 1. The listing shows only files with slow tests, so it does not show
where the run stopped. Push timeline (git reflog): coverage arrived with `ab306ad` (15:45:13); the
next push came 15 min 23 s later, about the 15-minute job timeout. So either the job timed out or
the next push cancelled it while still running. **Still a hypothesis**: the annotation has not
been read.

**Measured cause of high memory (local, 10-core Mac, peak RSS of the largest process).**
Eight test files created a fresh PGlite per test but closed them all in `afterAll`, holding up to
~20 databases per file. A single migrated+seeded PGlite costs ~1.2 GiB; a standalone script
(single run) holding 20 peaked at 1971 MiB vs 1340 MiB closing each one. In a single worker
(Vitest's default on a 2-vCPU runner) the files run one after another in the same process.

**Measurements (VALIDATE, independent and equivalent).** Two isolated copies of the tree, "before"
(the B30 changes reversed, 673 tests) and "after" (704 tests), sharing the same `node_modules`,
running identical commands alternately. The copies have no `.git`, so the same 9 `repo-hygiene`
tests fail in both (no database involved). "Cold" = Vitest's file-order cache cleared first.

| Run (MiB peak, wall time)              | Before                                            | After                                             |
| -------------------------------------- | ------------------------------------------------- | ------------------------------------------------- |
| `--coverage --maxWorkers=1` (CI proxy) | 2808, 78.9 s · 2696, 79.1 s · 3005 (cold), 79.0 s | 1702, 79.0 s · 1694, 79.3 s · 1692 (cold), 79.0 s |
| `--maxWorkers=1`, no coverage (cold)   | 2561, 65.4 s                                      | 1694, 66.9 s                                      |
| `--coverage`, default workers          | 1960, 44.3 s                                      | 1176, 30.3 s                                      |

Single-worker coverage runs (the CI stand-in; the three pairs above): 37–44 % lower,
approximately 2.6–2.9 GiB → 1.7 GiB. Single worker without coverage (the one cold pair): approximately
34 % lower (2561 → 1694 MiB). "After" is stable at 1692–1702 MiB;
"before" varies run to run (peak memory with many open databases depends on garbage-collection
timing). Earlier single samples taken during EVALUATE/APPLY (single-worker 4604 and 4259 MiB, and
the higher per-file "before" values) could **not** be reproduced, even with a cold cache, and are
superseded by these figures.

Per file, run alone (MiB, before → after): postgres-repository 2350 → 1453 · data/audit
2530 → 1533 · decide 2207 → 1696 · **users-auth-link 1441 → 1446: no measurable improvement** (four databases, one in each of four of its five tests) ·
errors 1400 → 1424 (reference; pattern unchanged). Not independently re-measured: accrual/run,
independence, submit and accrual/concurrency. Their APPLY single samples (run 3016 → 1684,
independence 2797 → 1696, submit 2784 → 1634, concurrency 1615 → 1427) are unverified; for the
files that were re-measured, the APPLY "before" values were higher than the re-measurement (for
errors, 1403 vs 1400 MiB, the difference is within measurement noise).

Coverage overhead: after the fix, single-worker runs show no measurable memory difference with or
without coverage (1692–1702 vs 1694 MiB), and coverage adds about 12 s (79.0 s vs 66.9 s). Before
the fix, the one cold pair differed by about 17 % in memory (3005 vs 2561 MiB). Coverage is not the
main memory factor; the open databases are.

**Confirmed vs not confirmed.** Confirmed locally: the memory reduction above, the causes (open
per-test databases, single-worker accumulation), and that V8 coverage is not the main factor.
**Not confirmed:** what cancelled the GitHub run (timeout vs concurrency cancel) and whether
memory caused it. That needs the run's annotation.

**Changed (tests and CI only; no production code, dependencies, thresholds, job timeout or concurrency).**
